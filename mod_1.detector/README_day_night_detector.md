# Отдельный модуль Day→Night-определения отражателей

Это независимый тестовый контур, созданный из камеры/ISAPI-части
`reflector_tracker_v5.31_optimized(1).py`. Основной скрипт не изменяется и не
импортируется.

## Состав

- `run_day_night_detector.py` — единственная точка запуска и простой GUI.
- `day_night_reflector_detector/hikvision_camera.py` — RTSP через FFmpeg и
  переключение Hikvision Day/Night через ISAPI.
- `day_night_reflector_detector/day_night_detector.py` — только определение
  положения отражателя. Здесь нет трекера, сглаживания и прогноза движения.
- `day_night_detector_config.json` — создаётся при закрытии приложения.
  Отдельное поле пароля в него не записывается. Если логин/пароль включены
  непосредственно в RTSP URL, URL сохраняется как введённый — ограничьте
  доступ к этому файлу.
- `day_night_diagnostics/` — автоматически сохраняемые результаты каждого
  поиска.

## Запуск

```bash
python -m pip install -r Requirements_day_night_detector.txt
python run_day_night_detector.py
```

Кроме Python-пакетов в системе требуются `ffmpeg` и `ffprobe`.

## Порядок проверки

1. Ввести прежний RTSP URL. Кнопка `↻` сформирует ISAPI URL по адресу камеры.
2. Логин и пароль можно оставить пустыми, если они находятся в RTSP URL.
3. Нажать `Подключить RTSP`.
4. Указать число отражателей.
5. Нажать `Задать рамки` и нарисовать P1…Pn прямо на текущем кадре. Масштаб и
   положение просмотра при этом не сбрасываются.
6. Нажать `Найти: Day→Night ×2`.

Камера выполняет последовательность:

```text
Day (несколько кадров) -> Night (несколько кадров)
Day (несколько кадров) -> Night (несколько кадров)
```

После анализа камера остаётся в Night.

## Что именно проверяет алгоритм

Каждая Pn анализируется полностью независимо и только в пределах своей ручной
рамки. Поиск за рамкой отсутствует.

Для каждого цикла строится исключительно положительный канал:

```python
positive_gain = max(Night - Day, 0)
```

`absdiff` не используется: потемнение светлого объекта не может стать
положительной вспышкой.

Кандидат обязан одновременно удовлетворять условиям:

- в Day рядом с Night-пятном есть компактное чёрное ядро;
- в Night оно стало ярким;
- прирост `Night - Day` превышает установленный минимум;
- площадь лежит в допустимом диапазоне;
- объект повторяется примерно в той же точке во втором цикле.

Центр вычисляется только по яркому Night-пятну. Используется медиана яркостных
центров нескольких уровней ядра, поэтому центр не должен перескакивать между
краями ореола. Day-изображение подтверждает объект, но не участвует в координате
центра.

## Основные параметры

- `Day: максимум чёрного` — максимальная яркость ядра отражателя в Day.
  Начальное значение `85`.
- `Night: минимум яркого` — минимальная яркость Night-пятна. Начальное значение
  `155`.
- `Мин. прирост Night−Day` — физический прирост яркости 0…255. Начальное
  значение `65`.
- `Мин./макс. площадь` — площадь связной части положительной маски.
- `Допуск Day/Night` — допустимый локальный сдвиг чёрного Day-ядра относительно
  яркого Night-ядра после переключения IR-cut.
- `Повторяемость` — максимальное расстояние между центрами двух Night-циклов.
- `Вес яркого ядра` — насколько сильнее наиболее яркие пиксели влияют на центр.
- `Мин. итоговый балл` — порог принятия повторившейся пары.
- `Мин. ромбовидность` — мягкая проверка формы. Значение `0` отключает
  отбраковку по форме, что полезно для размытого или пересвеченного ореола.

## Диагностика

После каждого запуска сохраняются:

- медианные кадры двух Day и двух Night;
- итоговое изображение с рамками, контуром яркой области и крестиком центра;
- по каждой Pn — положительный response и бинарная маска обоих циклов;
- `result.json` со всеми координатами, причинами отказа и числовыми метриками.

Основные причины отказа:

- `NO_BRIGHT_NIGHT` — в Night нет достаточно ярких пикселей;
- `NO_BLACK_DAY` — в Day нет чёрного ядра;
- `NO_POSITIVE_GAIN` — нет достаточного положительного прироста;
- `NO_VALID_COMPONENT` — вспышка есть, но площадь/форма не прошли фильтры;
- `NOT_REPEATABLE` — два цикла нашли разные положения;
- `LOW_SCORE` — признаки присутствуют, но итоговая достоверность мала.

Этот модуль предназначен именно для отладки первоначального Day→Night-поиска.
Он не должен выполнять сопровождение найденного отражателя.
